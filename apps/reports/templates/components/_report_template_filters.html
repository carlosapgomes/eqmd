{% comment %} Report-template discovery filters (S2/S3, design D5). The native GET form is the no-JavaScript contract: repeated ``tags``, ``tag_mode`` and the manual marker round-trip through the query string, while automatic specialty defaults stay out of it and are recomputed on every request. Typed values are rendered through Django escaping only. ``assets/js/report-catalogue-filter-form.js`` owns the catalogue draft state (``Alterações não aplicadas``) while ``assets/js/tag-selector.js`` owns the searchable selector; ``assets/js/report-template-discovery.js`` owns fragment transport/history. Creation shares this form but stays on its accepted JSON controller until S4: catalogue-only hooks carry a ``data-catalogue-`` prefix and creation-only behaviour is preserved. Native Apply carries ``tag_filter=manual`` on the submit button itself: a browser submits a named submit button only when it is the submitter, so Apply with every tag deselected is explicitly manual-empty, while initial entry (no form submission) has no marker and defaults apply. The ``data-discovery-marker`` input has no name, so it never submits; it only carries the current automatic/manual origin for the enhancement. {% endcomment %}
