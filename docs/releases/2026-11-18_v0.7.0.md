## Resumo Executivo

Release minor de descoberta e classificação de modelos de laudo por
tags do catálogo e de unificação da UX de filtros de tags na lista
de pacientes, mapa de enfermagem e catálogo/seletor de modelos de
laudo, com sete changes OpenSpec arquivados. Inclui **uma migração
aditiva** (`reports/0004_reporttemplate_tags`: campo M2M
`ReportTemplate.tags` + trilha de histórico) — o migrate gated do
upgrade **não é no-op** nesta release. Sem mudanças de permissões,
autenticação ou infraestrutura; risco baixo, rollback de app
tolerado (schema forward-only, campo novo é ignorado pela imagem
anterior).

## Rollback Plan

### Cenários para rollback

1. **Falha de health após o upgrade**: o próprio `upgrade.sh`
   imprime o comando de reversão do digest e restaura estáticos da
   versão anterior (`--profile ops run --rm init`).
2. **Bug funcional grave**: reverter o digest no compose e
   recriar; schema é forward-only e o campo M2M novo é ignorado
   pela imagem `0.6.0` (rollback curto tolerado, sem restauração
   de banco).
3. **Migration `reports/0004` falhar**: preservar logs/dump/
   `staging/upgrades/<ts>/`, identificar estado do schema
   (`django_migrations`) e decidir; restauração de banco é
   procedimento dedicado (`deploy/eon/cutover/rollback.md`),
   jamais automática.

### Passos para rollback

1. Comando de reversão impresso pelo `upgrade.sh` (digest no
   compose) + `up -d`.
2. `docker compose --profile ops run --rm init` para recompor
   estáticos da versão anterior.
3. Validar login e `/health/`.

**Tempo estimado para rollback:** < 15 minutos.
