**Data da release:** 2026-11-12
**Versão anterior:** v0.5.1
**Responsável:** [preencher]

## Resumo Executivo

Release minor de segurança clínica no perfil do paciente, com dois
changes OpenSpec arquivados e **sem migrações de banco**. A ação de
status `Emergência` deixa de ser exposta na interface (backend
preservado e testado para reativação futura) e a exclusão clínica
de pacientes passa a ser exclusiva do admin Django (superuser),
corrigindo um botão quebrado (`405`) e fechando a brecha de `POST`
forjado por médico. Inclui o plano documentado de upgrade do
PostgreSQL 15 para 18 (apenas docs, sem mudança de código). Risco
baixo; rollback por revert dos commits.

## Checklist de Rollout

### Pré-deploy

- [ ] Backup padrão do banco (esta release não inclui migrações).
- [ ] Validar em staging: perfil do paciente sem botão
      `Emergência`; sem controle `Excluir` em detalhe/lista para
      qualquer perfil; `POST /patients/<uuid>/delete/` por médico
      retorna `403`; ações restantes presentes (`Internar`,
      `Dar Alta`, `Ambulatorial`, `Declarar Óbito`,
      `Transferir Internamente` quando aplicável).

### Deploy

- [ ] Deploy padrão (sem janela especial; sem migração).
- [ ] Smoke test: lista e perfil renderizam; exclusão/restauração
      via Django admin funcionam.

### Pós-deploy (24h)

- [ ] Monitorar logs/erros como de rotina.
- [ ] Confirmar ausência de acessos a
      `/patients/<uuid>/delete/` em produção.

## Rollback Plan

### Cenários para rollback

1. **Fluxo de emergência precisa voltar**: revert de `7ea7972`
   (+`582bf1a` do archive); backend nunca foi removido, a
   reativação é apenas a transição de volta na template tag.
2. **Exclusão clínica precisa voltar**: revert de `b1e15ca`
   (+`1cf3b50` do archive). Atenção: o revert devolve o botão
   quebrado (`405`) e a brecha do `POST` forjado — preferir uma
   change dedicada de reativação com UI funcional.

### Passos para rollback

1. `git revert 1cf3b50 b1e15ca 582bf1a 7ea7972` (ou revert
   seletivo).
2. Redeploy da `v0.5.1` pelo procedimento padrão.
3. Sem migração de dados envolvida — nenhum backfill necessário.

**Tempo estimado para rollback:** < 15 minutos.
